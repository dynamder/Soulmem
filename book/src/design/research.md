# 设计旅程 · 调研：A-mem 与 HippoRAG 给了我们什么

> 我们一开始的想法很简单：能不能直接接入一个现成的 agent 记忆 / RAG 框架？于是调研了
> 当时涌现的各种方案，最终锁定了两个重要参考：**A-mem** 和 **HippoRAG**。今天的 SoulMem
> 架构，很大程度来自它们的灵感——但我们也清楚地看到了它们与角色扮演场景的错位。

## 为什么一开始想用现成的

记忆系统是个大工程。如果社区已经有成熟的 agent memory 或 RAG 框架，直接接入是最省力的
路径——当时各类 agent memory 方案确实在涌现，看起来选择很多。

## A-mem：图结构的启蒙

**A-mem**（Agentic Memory）是一种 Agentic RAG 方案，也是我们最早锁定的参考之一。

它给我们的最大启发是**图结构**：记忆不是一堆独立的片段，而是互相连接的节点——这与
"记忆可以联想"的直觉天然吻合。

但在 alpha 版本的实验中，我们也发现了它和角色扮演场景的错位：

- A-mem 把所有记忆节点都当作同一个 `Note`，**不加区分**；
- 这带来的直接后果是：**很难写"自进化"算法**。

什么叫"自进化"？比如：把一次具体经历（情境记忆）慢慢抽象成一条长期认知（语义记忆），
或者从反复出现的情境中长出行为习惯（程序性记忆）。这要求系统*知道*不同类型的记忆该
如何不同地处理。当一个系统把所有记忆都塞进同一种节点时，它就没有办法针对"情境"做
情境的事、针对"行为"做行为的事。

这个观察直接推动了 SoulMem 的**三类记忆**设计——我们会在 [为什么三类记忆](memory-taxonomy.md) 里展开。

## HippoRAG：PPR 联想的来源

**HippoRAG** 是另一个重要参考。它的核心思想：用知识图谱存储记忆，检索时用
**Personalized PageRank（PPR）** 在图上扩散，模拟人脑的联想过程。

这是 SoulMem 中 PPR 算法的**直接设计来源**。我们认同"联想 = 图上的扩散"这个建模方式：
从当前话题对应的节点出发，让重要性沿着图的边扩散出去，被"激活"的节点就是联想结果。

## 关键洞察：这些框架是为"代码 agent"设计的

调研到最后，我们意识到一个根本性的错位：

> 当时的 agent memory / RAG 框架，大多是为**代码 agent** 这类场合设计的——目的是
> **精确**地记录代码库事实、用户经验，并**高效、准确**地检出。

而角色扮演的场合恰恰相反：

| | 代码 agent 记忆 | 角色扮演记忆 |
|---|---|---|
| 目标 | 精确记录、准确检出 | 像人一样记住重要的、联想相关的 |
| 遗忘 | 不该忘（知识要完整） | **人会遗忘**，遗忘是特性不是缺陷 |
| 联想 | 少而准 | **天马行空**的联想恰恰是魅力所在 |
| 记忆演化 | 基本不变 | 随相处时间**演化**（巩固/调整/遗忘） |

"人会遗忘"和"人会有天马行空的联想"——这两点，是现成框架**不打算解决、甚至刻意回避**
的。而我们恰恰认为这才是角色扮演记忆的灵魂。

## 结论：不能直接套用，要自己设计

所以 SoulMem 的决定是：**借鉴 A-mem 的图结构和 HippoRAG 的 PPR 联想，但重新设计记忆的
数据模型和生命周期**，让它服务"人一样的记忆"，而不是"精确的知识库"。

这带来三个核心设计决策：

1. **三类记忆**：情境 / 语义 / 程序性，各自有独立的结构和处理方式（自进化的前提）；
2. **图 + PPR**：用图组织全部记忆，用 PPR 做联想（HippoRAG 的启发）；
3. **遗忘是一等公民**：模拟遗忘曲线，模糊而非删除（这是角色"会变"的来源之一）。
