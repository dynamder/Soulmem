# 设计旅程 · 为什么必须自部署

> 这一章讲一个看似"工程细节"、实则关乎产品灵魂的决定：为什么 SoulMem 必须能跑在
> 用户自己的电脑上，而不是作为云端服务提供。

## 赛博生命意味着什么

赛博生命的典型场景是**长期的个人陪伴**：一个数字存在，陪你几个月、几年。它知道你的
喜好，记得你们的经历，是你生活的一部分。

对于这样的东西，"它住在哪里"很重要。

## 三条硬理由

### 1. 隐私

陪伴意味着大量私密信息：你的情绪、你的经历、你最不想让别人知道的事。

如果角色扮演服务由外部公司提供，这些数据就会经过别人的服务器。商业产品的隐私保证，
对用户来说是无从验证的——你只能"相信"。对"把自己的一部分交给数字生命"这件事来说，
把数据留在自己电脑上，是唯一让人安心的方案。

### 2. 可靠性：陪伴不能"被迫离开"

更致命的问题是**不可控的外部风险**：

- 政策变化可能让服务下架；
- 公司运营变化（倒闭、转型、涨价）可能让服务终止；
- 你陪伴了半年、一年的事物，可能因为一条公告就永远消失了。

"陪伴多时的事物莫名其妙地被迫离开"——这是用户最难以接受的事。自部署意味着：**只要
你的电脑还在，你的数字伙伴就还在**。没有人能把它从你身边拿走。

### 3. 大众可及性

赛博生命不应该是有钱人的玩具。自部署 + 家用电脑运行，让"拥有一个数字伙伴"成为普通
人也能负担、也能掌控的事情——这正是 Soul Plan 想要的未来。

## 自部署带来的技术约束

接受"自部署"这个前提，就接受了一连串技术约束，它们反过来塑造了 SoulMem 的形态：

| 约束 | 后果 |
|------|------|
| 家用笔记本（资源受限） | 不能跑超大模型 → 少用 LLM、算法为主（见 [技术选型](tech-choices.md)） |
| 用户不是开发者 | 一键运行 → 编译为二进制的 Rust（见 [技术选型](tech-choices.md)） |
| 没有云端基础设施 | 不依赖外部数据库服务 → 数据落在本地（当前以文件形式，未来演进见系统概览） |

## 小结

- 自部署是**产品灵魂**问题，不是工程偏好：隐私、可靠性（陪伴不被迫离开）、大众可及；
- 它带来的资源约束，直接催生了"Rust + 少用 LLM + 本地存储"这一整套技术形态；
- 记住这一点，后面看任何设计决策，都能找到它的影子。
