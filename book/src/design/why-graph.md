# 设计旅程 · 为什么用图来组织记忆

> 记忆最迷人的地方是联想。这一章讲：为什么"图"是表达记忆最自然的结构，以及图给我们
> 带来了什么。

## 联想是什么

先想一个生活中的例子：

> 你看到"钟离假死"这个梗，会想到"米哈游"；看到"雨天"，会想到某个一起躲过雨的下午。

这些联想，靠的是记忆之间的**连接**——不是字面上的相似，而是"因为某些原因，它们被
关联在一起了"。

## 为什么向量搜索不够

最经典的 RAG 思路是**向量搜索**：把每段记忆变成向量，检索时找"语义上最相似"的几条。

它的问题是：**它不知道连接**。

- **多跳**：假设用户问"姚明妻子的父亲的出生地是哪里"。向量搜索可以找到"姚明"、
  "姚明的妻子"、甚至"叶莉"——但要凑齐"叶莉的父亲 → 出生地"这条链路，向量空间里的
  距离帮不上忙。
- **联想**："钟离假死"和"米哈游"在向量空间里距离很远（一个是游戏角色梗，一个是公司
  名），但这两个实体在现实中是强相关的。向量搜索找不到这种关联。

## 图：把"连接"显式地画出来

图结构的思路很直接：**把记忆当作节点，把关联当作边**。

- 节点 = 记忆（情境 / 语义 / 程序性）；
- 边 = 关联（"涉及"、"导致"、"触发"、"是……的一部分"……），边上还可以带**权重**
  （连接强度）。

一旦有了图，联想就变成了一件"图上自然发生"的事：从起点节点出发，沿着边扩散，走过的
路径就是联想链。

```text
[钟离假死] --涉及--> [游戏角色] --属于--> [米哈游]
```

## 图带来的三个好处

### 1. 多跳推理变得可能

沿着边一步一步走，"姚明 → 叶莉 → 叶莉的父亲 → 出生地"这样的链路，在图上就是一次
"行走"。图算法（比如我们用的 PPR）天然支持这种多跳。

### 2. 联想可以"天马行空"

只要两个节点之间有边（不管它们向量上像不像），扩散就能到达。这模拟了人的联想——人
的联想本来就不是"语义相似"，而是"被关联过"。

### 3. 连接强度可以动态变化

边上可以带权重。而权重可以被算法调整（比如反复共同激活的边变强——类似人脑的 LTP/
LTD 机制）。这给"记忆演化"提供了抓手：**连接强度的变化，就是角色性格和行为习惯的
成长过程**。这一点在遗忘算法里还会用到。

## 图 + 算法 = 记忆系统的工具箱

图结构还有一个实际好处：**图算法是现成的工具箱**。

- **联想**：PPR（Personalized PageRank）——从起点扩散重要性（HippoRAG 的启发）；
- **遗忘**：连接强度的衰减（艾宾浩斯曲线）；
- **巩固**：把"经常一起出现的节点"合并、抽象成更高层的节点；
- **检索**：相似度找到起点，PPR 扩散找关联。

如果我们用列表或向量库来存记忆，这些操作要么做不了，要么要自己发明轮子。图结构让我们
能站在图算法的肩膀上。

## 小结

- 记忆的本质是**关联**，而图是表达关联最直接的结构；
- 向量搜索适合"相似"，不适合"联想"和"多跳"；
- 图带来：多跳推理、自由联想、可调节的连接强度；
- 图算法（PPR、衰减、巩固）是记忆系统的天然工具箱。
