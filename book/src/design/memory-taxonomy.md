# 设计旅程 · 为什么是三类记忆

> 我们已经知道记忆分成情境、语义、程序性三类。这一章讲：**为什么是这三类**，以及这个
> 划分如何让"自进化"成为可能。

## 答案的开头：参考人脑

人类认知科学把记忆分为多种类型，其中最常见的一种划分就是**情境（episodic）、语义
（semantic）、程序性（procedural）** 三类。SoulMem 直接借鉴了这个分类——不是因为"人脑
有所以我们要有"，而是因为**这个划分恰好对应三种完全不同的运作方式**，值得分开处理。

## 三类记忆：三种不同的运作方式

### 情境记忆：一次性的、有时间的

> "上周三中午，和用户在街角麻辣烫店，被辣到了。"

- 是一次**事件**：有明确的时间、地点、人物；
- 是**唯一的**：那次麻辣烫只发生了一次；
- 作用是：让角色记得"我们共同经历过什么"。

### 语义记忆：剥离了时间的知识

> "用户喜欢苦味，讨厌甜味。"

- 是**知识**：从多次经历中提炼出来的、长期有效的认知；
- 是**去重后的**：一百次"用户点了苦咖啡"，最终沉淀成一条"用户喜欢苦味"；
- 作用是：让角色"懂"用户，而不是只"记得"发生过什么。

### 程序性记忆：不是"知道"，是"会"

> "紧张的时候摸辫子。" / "被关心的时候，嘴上否认（傲娇）。"

- 是**行为模式**：在什么情境下，角色倾向于怎么做；
- 是**可触发**的：检索时如果情境匹配，这个行为模式会进入角色的"行动提示词"；
- 作用是：让角色的行为有**一致性**——同样是傲娇，昨天和今天表现一致，但会随着经历
  缓慢演化。

## 为什么必须分开：自进化的前提

回顾 [调研章节](research.md)：A-mem 把所有记忆当作同一种 `Note`，导致我们**写不出自进化
算法**。为什么？

自进化，本质上是**把一种记忆加工成另一种记忆**的过程：

```text
反复发生的情境记忆 ──巩固──▶ 语义记忆（"用户喜欢辣"）
特定情境 + 反复出现的行为 ──▶ 程序性记忆（"紧张就摸辫子"）
```

而"加工"这件事，要求系统**知道每种记忆的形态**：

- 情境记忆有 `narrative`（叙述）、`time_span`（时间）、`context`（上下文：地点、人物、
  情绪、感官……）——因为它们是一次事件，必须能表达"什么时候、在哪、和谁、什么感觉"；
- 语义记忆有 `content`（内容）、`aliases`（别名）、`concept_type`（实体/抽象）——因为
  它们是概念，必须能去重、能消歧、能被引用；
- 程序性记忆有 `trigger`（触发条件）和 `action`（行为）——因为它们是要被"触发"的，
  必须能表达"什么情况下做什么"。

如果所有记忆都是同一个无结构节点，系统就无从知道"该对这段记忆做什么加工"。分开之后，
**每一种记忆都有自己该有的字段、自己的算法、自己的生命周期**——自进化才有了落脚的
地方。

## 三类记忆如何协作

分开不等于孤立。三类记忆是一张图上的三种节点，互相连接：

- **情境 → 语义**：经历反复出现，抽象成知识；
- **情境/语义 → 程序性**：特定情境反复触发特定行为，长成习惯；
- **语义 ↔ 程序性**：语义节点可以连接行为——比如"被关心"这个概念连接到"否认关心"
  这个行为。语义联想的路径**不会直接触发**行为，只有情境触发的才会（详见系统概览），
  这个区分让角色既能"意识到"自己的习惯，又能"自然表现"出来。

## 小结

- 三类记忆对应三种运作方式：**经历、知识、行为**；
- 分开处理的直接收益是**自进化算法有了操作对象**；
- 三类记忆通过图连接协作，构成完整的记忆生态。
