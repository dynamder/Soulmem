# 核心概念 · 长期记忆、工作记忆与滑动窗口

上一章我们认识了记忆图：它承载着角色全部的情境、语义、程序性记忆。但就像上一章提到的，SoulMem并不只维护一个图，也不只有图一种形式来组织记忆——在这一章，我们将看到SoulMem的三种记忆层级：**长期记忆、工作记忆与滑动窗口**。

先问一个直觉上的问题：既然长期记忆里什么都有，那每次对话直接把整个图丢给模型不就行了？

显然不行。图会随着相处时间不断长大，一次对话却只需要其中很小的一部分；而且人的记忆本来就不是这样运作的——你不可能同时"想起"所有事，你只会想起与当下有关的那些。SoulMem 用三个层级来模拟这件事。

## 三个层级

```mermaid
graph TB
    L["长期记忆<br/>全部记忆：沉淀下来的一切"] -->|激活相关部分| WM["工作记忆<br/>当前对话正在使用的子图"]
    WM -->|输入缓冲| SW["滑动窗口<br/>最近几轮对话"]
```

### 长期记忆：角色的整个人生

长期记忆是记忆系统的"仓库"：所有沉淀下来的情境、语义、程序性记忆，以**图**的形式存放在这里。它体积大、变化慢，是角色的"人格底座"。

以小红为例。和她相处三个月，你们一起吃的麻辣烫、她喜欢的苦味、她紧张时摸辫子的习惯——这一切最终都会沉淀在长期记忆里。长期记忆不随对话结束而消失，它是小红"整个人生"的存档。

### 工作记忆：你现在正在想的事

工作记忆是"激活"出来的子图——从长期记忆里，把当前对话相关的部分临时取出来使用。

打个比方：长期记忆是你的书房里所有的书；工作记忆是你此刻摊开在桌上、正在读的那几本。

工作记忆有两个特点：

- **它主要来自长期记忆**：检索把相关的节点从图上"点亮"，临时组成一个子图；此外，本次对话新产生、还没沉淀回去的记忆也先待在这里；
- **它变化频繁**：对话中产生的新记忆先进入工作记忆，检索也发生在工作记忆上。

> *注*：严格来说，工作记忆 = 从长期记忆激活出来的子图 + 本次对话新产生、尚未沉淀回长期记忆的内容。

### 滑动窗口：最近几轮对话

滑动窗口是工作记忆的"输入缓冲区"——记录最近几轮用户和 AI 的对话。它模拟人的短期记忆：容量有限，新的进来，旧的滑出去。

滑出的信息会怎样？

- **被打上标记的**：触发一次摘要——窗口内容被 LLM 压缩成一条"摘要记忆"，摘要随对话持续累积，等待被巩固；
- **没被标记的**：随窗口滑出而丢失——就像你不记得昨天午饭具体吃了什么。

窗口内最近的对话内容，在检索时**无条件**进入上下文。因为"刚刚说过的话"无论如何都该被记得，不需要经过联想。

## 为什么需要三个层级？

如果把所有记忆都堆在一个大图里、每次对话全量使用，会出现什么问题？

#### 上下文装不下

模型的上下文窗口是有限的。三个月、几百轮对话积累下来的记忆，不可能全部塞进上下文。长期记忆负责"存得下"，工作记忆负责"取所需"——每次对话只激活一小部分。

#### 检索要有焦点

联想是从"当前话题"出发的：你说"晚上吃啥"，系统要想起的是和"吃"有关的记忆，而不是三个月前的一件琐事。如果所有记忆平铺在一起，联想就没有出发点和聚焦的方向。滑动窗口提供了"当下"的焦点，工作记忆提供了"从焦点联想出去"的空间。

#### 不是每条信息都值得沉淀

人不会把每句话都记住。如果每轮对话都直接变成永久记忆，长期记忆会迅速被垃圾淹没。滑动窗口 + 摘要，让信息先以廉价的方式待着，只有值得的才被巩固、沉淀——这与人记住重要的事、忘掉琐事的节奏一致。

#### 人本来就是这样运作的

人**不能**同时记住所有事 → 滑动窗口限定了"短期"的容量；人**能**想起很久以前的事 → 长期记忆以图组织，支持联想检索；人**会**把反复出现的经历沉淀成习惯和认知 → 巩固机制。

> 这也是 SoulMem 的核心设计之一：**三层各司其职——长期记忆负责"沉淀"，工作记忆负责"联想与使用"，滑动窗口负责"最近的对话"。** 分层不是为了复杂，而是为了让每一层都能用最适合自己的方式被处理。

## 一次对话的完整旅程

让我们把三个概念串起来，看一次完整对话里发生了什么：

```mermaid
graph TB
    U[用户说话] --> W[进入滑动窗口]
    W -->|带标记的信息滑出| S[摘要 → 摘要记忆]
    S -->|空闲时| C[巩固 → 生成记忆节点]
    C --> L[长期记忆]
    Q[用户提问] --> R[检索: 相似度 + PPR 联想]
    R --> A[激活长期记忆子图 → 工作记忆]
    A --> CTX[工作记忆 + 窗口内容 → LLM 上下文]
    W --> CTX
    CTX --> AI[AI 回复]
    AI --> W2[回复也进入窗口]
```

1. 用户说话 → 进入**滑动窗口**；
2. 带标记的信息滑出 → 触发**摘要**，窗口内容被 LLM 压缩成摘要记忆（随对话累积）；
3. 空闲时，摘要记忆被**巩固**成记忆节点，与高频激活的节点建立连接，写入**长期记忆**；
4. 用户提问 → 系统在**长期记忆**上检索（相似度找到种子，PPR 联想扩散），激活相关子图成为**工作记忆**；
5. 窗口内容（短期）+ 工作记忆（联想结果）→ 组成 LLM 的上下文；
6. AI 回复 → 也进入窗口，开始下一轮循环。

这三层的配合，是 SoulMem 整个系统运转的骨架。后面的章节（设计旅程、系统概览）会逐一展开每一层的实现细节；接下来，我们先看一份记忆如何在这三层之间度过一生。
