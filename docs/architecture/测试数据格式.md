# 检索算法测试数据格式

## 数据流

```
Scraper (extract_*.json)          Questioner (question_*.json)
        ↓                                   ↓
   图结构和节点                       查询 + 期望结果
        ↓                                   ↓
        └─────────── RetrTestCase ──────────┘
                           ↓
              soul-tune 评测引擎
```

两份 JSON 独立生成，在 `RetrTestCase` 中绑定后送入评测引擎。

---

## 一、Scraper 图格式 (`extract_*.json`)

由 Scraper 从角色素材中提取，描述记忆图谱的静态结构。

### 顶层结构

```jsonc
{
  "graph": {
    "nodes": [ /*...*/ ],
    "edges": [ /*...*/ ]
  },
  "summary": "十六夜咲夜的完整背景摘要..."
}
```

### Node

```jsonc
{
  "node_id": "sem_self",
  "tags": ["自我", "女仆", "时间能力", "红魔馆"],
  "mem_type": {
    "mem_kind": "Semantic",
    "content": "十六夜咲夜",
    "aliases": ["咲夜", "女仆长", "红魔馆的女仆长"],
    "concept_type": "Entity",         // Entity | Abstract
    "description": "我是十六夜咲夜，红魔馆的女仆长..."
  }
}
```

字段映射到 soul-mem 类型：
| JSON 字段 | SoulMem 类型 |
|-----------|-------------|
| `tags` | `MemoryRetrieveQuery.tags` → tag embedding 的各维度 |
| `mem_kind == "Semantic"` | `MemoryType::Semantic(SemMemory)` |
| `mem_kind == "Situation"` | `MemoryType::Situation(SituationMemory)` |
| `content` | `SemMemory.content` |
| `aliases` | `SemMemory.aliases` |
| `concept_type` | `SemMemory.concept_type` |
| `description` | `SemMemory.description` |

### Edge

```jsonc
{
  "link_id": "link_1",
  "source_id": "sem_self",
  "target_id": "sem_remilia",
  "intensity": 1.0,
  "link_type": {
    "link_kind": "Sem",
    "verb": "效忠于",
    "confidence": 1.0
  }
}
```

字段映射：
| JSON 字段 | SoulMem 类型 |
|-----------|-------------|
| `source_id`, `target_id` | 引用节点的 `node_id` |
| `intensity` | `MemoryLink.intensity` |
| `link_kind == "Sem"` | `MemoryLinkType::Sem(SemMemLink)` |
| `link_kind == "Situation"` | `MemoryLinkType::Situation(SituationMemLink)` |
| `link_kind == "Proc"` | `MemoryLinkType::Proc(ProcMemLink)` |
| `verb` | 仅供 LLM 阅读，不参与检索计算 |
| `confidence` | `SemMemLink.confidence` / 或 `MemoryLink.intensity` |

### 约束

- `node_id` 在同一文件中必须唯一
- `edge` 的 `source_id` / `target_id` 必须引用已存在的 `node_id`
- `intensity` 范围 [0.0, 1.0]
- `confidence` 范围 [0.0, 1.0]

## 二、Questioner 输出格式 (`question_*.json`)

由 Questioner 在参考图结构后生成，包含查询及期望结果。

### 顶层结构

```jsonc
{
  "graph_source": "extract_sakuya.json",     // 指向生成时所基于的图文件
  "scenario_id": "sakuya_scarlet_mansion",   // 场景标识
  "queries": [ /*...*/ ],                    // 原子查询
  "query_sets": [ /*...*/ ]                  // 同意图多表达变体集合
}
```

### Query

```jsonc
{
  "priority": 1,
  "tags": ["蕾米莉亚", "主人", "红魔馆"],
  "variant": {
    "variant_kind": "Semantic",
    "units": [
      {
        "concept_identifier": "蕾米莉亚·斯卡雷特",
        "description": "红魔馆的大小姐，咲夜的主人"
      }
    ]
  },
  "expected": {
    "must_include": ["sem_remilia", "sem_self"],
    "may_include": ["sem_scarlet_mansion", "sem_flandre"],
    "expected_actions": []
  }
}
```

### ExpectedResult

| 字段 | 含义 | 评测规则 |
|------|------|---------|
| `must_include` | 必须出现在检索结果中的节点 | 缺失即判 FAIL |
| `may_include` | 出现则加分，不出现不扣分 | 用于 NDCG / Recall@K 计算 |
| `expected_actions` | 期望命中的 Procedure 节点 | 计算 Action Hit Rate / Action Recall@K |

`must_include` 和 `may_include` 中的 node_id **必须**存在于 `graph_source` 所指向的图文件中。

### QuerySet

同一检索意图的 2–8 种不同措辞：

```jsonc
{
  "set_id": "query_master_importance",
  "description": "查询咲夜最重要的主人相关记忆",
  "queries": [
    { /* 完整 Query 1: 效忠于谁 */ },
    { /* 完整 Query 2: 谁赐予名字 */ },
    { /* 完整 Query 3: 最重要的人 */ }
  ]
}
```

QuerySet 用于测试检索系统对不同口语化表达的**泛化鲁棒性**。

字段映射到 `RetrTestCase`：
| Questioner 字段 | RetrTestCase 字段 |
|----------------|-------------------|
| `scenario_id` | `scenario_id` |
| `graph_source` | `graph_path`（运行时解析为路径） |
| `queries[].priority` | `TestCaseQuery.priority` |
| `queries[].tags` | `TestCaseQuery.tags` |
| `queries[].expected.must_include + may_include` | `TestCaseQuery.expected_ranking` |
| `queries[].expected.expected_actions` | `TestCaseQuery.expected_actions` |

## 三、评测过程

### 输入

```
source/
├── graphs/
│   ├── extract_sakuya.json
│   ├── extract_reimu.json
│   └── extract_marisa.json
└── questions/
    ├── question_sakuya_001.json
    ├── question_reimu_001.json
    └── question_marisa_001.json
```

### 执行步骤

1. **加载图**：`extract_*.json` → `GraphData { nodes, edges }` → `MemoryCluster`
2. **加载查询**：`question_*.json` → `RetrieveAssessInfo`
3. **构建 TestCase**：`RetrTestCase { scenario_id, graph_path, cases }`
4. **对每个 case**：
   - 从 `tags` 构造 tag embedding
   - 从 `variant` 构造 `MemoryRetrieveQueryVariant`
   - 组合为 `MemoryRetrieveQuery → embed → MemoryRetrieveQueryEmbedding`
   - 调用 `DefaultPipeline.retrieve()`
   - 比较结果和 `ExpectedResult`，计算指标

### 输出指标

| 指标 | 来源 | 说明 |
|------|------|------|
| Recall@K | `must_include` + `may_include` vs 检索结果 | K ∈ {1, 3, 5, 10} |
| Precision@K | 同上 | - |
| MRR | 第一个相关结果的排序倒数 | - |
| NDCG@K | 排序质量（理想排序 vs 实际排序） | - |
| Hit Rate | 至少一个相关结果是否出现 | - |
| Action Hit Rate | `expected_actions` vs 检索动作 | - |
| Action Recall@K | 同上 | K ∈ {1, 3} |
