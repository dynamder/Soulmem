# 激发测试（excitation）设计

> soul-tune 是**效果测试框架**：不读取算法内部常量、不假设激发次数如何进入衰减公式，
> 只通过公开接口驱动与观测，断言只针对可观察效果。本测试验证的核心命题：
> **记忆被激发/提取后，遗忘被延缓**。

实现位置：`crates/soul-tune/src/engine/forget.rs` → `ForgetPipelineSuite::run_excitation_case`。

## 1. 接口契约（测试依赖的全部端口）

| 方向 | 公开接口 | 用途 |
|---|---|---|
| 激发（输入） | `MemoryNote::retrieval_increment()` | 模拟记忆被提取/唤起 |
| 老化（输入） | soul-tune 侧 `apply_aging()` | 回拨 `last_forget_time`，不触碰算法逻辑 |
| 全图刷新 | `compute_all_missing_degrees()` | 驱动算法更新状态 |
| 观测（输出） | `current_missing_degree()` / `missing_degree()` | 读取可观察结果（只读，不写回） |

## 2. 测试结构

1. 图克隆两份（**对照** / **实验**），施加同一 72h 老化；
2. 实验组按设计剂量梯度 `{0, 1, 3, 10, 30, 50, 100}` 激发
   （固定种子洗牌节点顺序后循环分配 → 确定性、类型混合；**每个节点以自身为对照**）；
3. 三个检查点（24h / 48h / 72h）逐节点配对比较：
   - 只读 `current_missing_degree`（不写回 `last_forget_time`，全程同一条模拟时间轴）；
   - 每个检查点先施加该点激发的批次，再观测（E4：激发前后同刻比对）。

### 三种时机子场景（同一批总次数，各自独立跑一遍全部断言）

| 子场景 | 时机 | 验证重点 |
|---|---|---|
| `excitation-early` | t=0 全部激发 | 全周期延缓 |
| `excitation-spaced` | 24/48/72h 分批均布 | 事件研究：分批出现延缓 |
| `excitation-late` | t=48h 全部激发 | 激发前无差异、激发后出现延缓 |

测试**不假设**时机是否影响结果（当前算法为次数制，时机不影响最终缺失度；
若将来改为"激活回鲜"语义，本测试依然成立）。

## 3. 断言清单（E1~E6，全部基于可观察效果）

**统计口径**：只统计**参与遗忘**的节点（SemMemory / SpecificSituation）；Procedure 类型
不参与遗忘机制，从一开始就排除在激发测试的统计与观测之外。对照组（未激发基线）=
全体参与节点的未激发 md 平均；激发组效果 = 仅被激发（dose>0）节点的平均 md / 延缓。

| # | 断言 | 防的回归 |
|---|---|---|
| E1 | 每个被激发节点 72h `Δmd = md对照 − md实验 > 1e-3` | 激发彻底失效（核心命题） |
| E2 | 每个未激发（dose=0）节点 `\|Δmd\| < 1e-4` | 激发产生全局副作用（延缓非激发所致） |
| E3 | 剂量组平均 md 随剂量单调下降；饱和点（50 与 100 次）效果相同 | 剂量-反应关系破坏 / 封顶失效 |
| E4 | `0 ≤ md ≤ 1`；激发后同刻 md 不上涨；对照序列随时间单调不减 | 数值越界 / 激活恶化记忆 |
| E5 | 事件研究：已激发节点在激发后的检查点出现延缓，未激发的不出现 | 延缓与激发无因果关联 |
| E6 | 同一场景两次运行结果完全一致（固定模拟时钟 + 固定种子） | 非确定性 / 时间抖动 |

## 4. 延缓指标（时间域，纯观测）

- 观测检查点：**每 2h 一个（36 点，0→72h）**，曲线平滑；关键展示点（detail 文本 /
  事件研究摘要）取 24/48/72h；
- 每个节点从检查点序列线性插值求"到达 md=0.5（遗忘到一半）的时间"；
- **延缓小时数 = t实验 − t对照**（同节点 id 配对）；实验组窗口内未达阈值时报告下限；
- 报告每个剂量的均值/最小延缓、未达阈值节点数，形成可人工复核的效果表。

## 5. 质量门槛

- dose ≥ 3 的组平均 `Δmd(72h) ≥ 0.05`：防止"理论上延缓、效果微不可察"的假通过；
- 全程无 LLM、无网络、确定性，可进 `cargo test` 与 CI。

## 6. 预期数值参考（当前实现推导，仅供人工核对，不进断言）

| dose | 72h md | 到达 md=0.5 时间 | 延缓小时数 |
|---|---|---|---|
| 0 | 0.875 | 24h | — |
| 1 | 0.849 | 26.4h | +2.4h |

- FRB 绑定无需重新生成（`run_forget` 的 mode 参数仍是 `String`）。

## 8. 结果解读（怎么看测试是否通过）

1. **核心命题**：激发组的遗忘是否被延缓。看汇总页平均曲线——实线（激发）应整体
   低于虚线（对照）；数值上 `Δmd(72h) > 0` 且 dose≥3 组平均 `Δmd ≥ 0.05`（质量门槛）。
2. **剂量-反应**：被激发次数越多，遗忘越慢（观测页不同节点的曲线拉开差距）；
   50 次与 100 次效果相同 = 算法封顶边界，属预期。
3. **因果归因**：E5 事件研究——未激发检查点上激发组与对照组无差异、激发后才出现
   差距；E2 保证 dose=0 节点无泄漏。若这两条不成立，说明延缓不是由激发引起。
4. **用例通过条件**：E1~E6 全部满足（`run_excitation_case` 内部断言，任一失败则该
   用例整体失败并输出具体节点/剂量组定位）。
5. **指标释义**：
   - `缺失度 md`：0=新鲜，1=完全遗忘（md=0.5 即遗忘到一半）；
   - `延缓小时数`：激发组比对照晚 N 小时到达 md=0.5（半衰期延长的实际效果）；
   - `封顶验证`：激活 >50 次不再额外延缓，50 与 100 次 Δmd≈0。

## 9. 前瞻性接口建议（暂不改动，仅记录）

`retrieval_increment()` 会把 `last_accessed_time` 写为真实 `Utc::now()`。当前衰减公式
不使用该字段，因此本测试仍完全确定。**若将来实现"激活回鲜"语义开始使用该字段**，
soul-tune 应要求 core 层提供 `retrieve_at(DateTime<Utc>)`（或 builder 支持），
使测试能用模拟时刻激发、保持确定性。届时本测试的三种时机子场景将自动
覆盖"回鲜"行为（越晚激发延缓越强），无需修改断言框架。
